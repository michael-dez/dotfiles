# i3 (BCLT)

`i3/config`, `i3/i3blocks.conf` and `i3/scripts/` are the EndeavourOS i3 template
(upstream: `endeavouros-team/endeavouros-i3wm-setup`) plus local edits, and
`picom/picom.conf` is the stock picom sample; their upstream comments and licence
headers are left in place. Only locally written rationale is here.

## Passthrough mode (Moonlight streams)

`i3/config`: `mode "passthrough"`, entered/left with `Mod4+Escape`.

**The problem.** i3 places a passive X grab on every `$mod` binding, and `$mod` is
`Mod1`, which is *both* Alt keys. A passive grab fires before the focused window
sees the key, so while BCLT is streaming bcpc with Moonlight every host binding is
swallowed locally: Alt+Return opens a terminal on the laptop rather than the host,
Alt+d runs the laptop's launcher. Right Alt doesn't escape it: Hyprland on bcpc
uses Right Alt as its mod (`kb_options=lv3:ralt_switch` makes it Mod5 there), but
on BCLT X still reports `Alt_R` as Mod1, so i3 grabs it like the left one.

**The mode** has one binding, the one that leaves it. While active, i3 grabs
nothing, so every key reaches Moonlight and through it the host. `Super+Escape`
because Hyprland on bcpc binds nothing to Super, so the host can never want this
combination back (unlike any Alt combination, which is the whole problem). The bar
shows "passthrough" while active.

**Try Moonlight's own setting first**: Settings -> Input -> "Capture system
keyboard shortcuts" = "In fullscreen" or "Always". That takes an active X keyboard
grab, suspending i3's passive grabs for the length of the stream, with no mode
switching. The mode is what still works when that's Never, or the stream is
windowed.
